It is shown/hidden by Alpine rather than swapped in by htmx, so it needs its own dialog semantics and focus handling: role/aria-modal so it is announced as a dialog at all, a Tab trap so focus cannot land on a control behind the scrim, and dialogSync to hand focus back to whatever opened it. This dialog creates a SLICE, always — Slice is the only unit of work now, so there is no separate Ticket to fork into. Area decides the destination directly: pick one and the slice files there immediately; leave it empty and the slice waits, area-less, in the Inbox. Both are real destinations (see inbox_slices()/filed_slices() in core/services/slices.py), not a draft state on the way to becoming something else — which is what made this dialog worth rewriting: it is the one surface that defines "slice" for a new user, and it re-serves that definition every time it opens. {% endcomment %}
